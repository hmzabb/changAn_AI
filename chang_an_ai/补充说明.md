# 长安文旅探店助手 · AI 服务（Python）

黑马点评（Java Spring Boot）之上的 AI 智能层：RAG 智能问答 + 笔记 AI 辅助 + 探店 Agent。
与 Java 端通过 HTTP 集成（拉数建库 + Agent 工具实时查询 + Java 转发非流式接口），
流式聊天由 nginx 直连本服务。详见项目根目录《项目说明.md》。

## 架构一览

```
浏览器 :8080（nginx）
 ├─ /api/ai/chat|health|admin → 直连本服务 :8000（SSE proxy_buffering off）
 ├─ /api/ai/assist/*          → Java :8081 → 转发本服务（非流式，Java 层鉴权）
 └─ 其余 /api/*                → Java :8081（业务）
本服务 ──httpx──► Java :8081（建库拉数 / Agent 工具实时查询）
本服务 ──► DeepSeek（对话/生成/tool calling）
本服务 ──► SiliconFlow（bge-m3 embedding / bge-reranker）
本服务 ──► Milvus :19530（Docker standalone，collection: changan_kb）
```

## 快速开始

```bash
# 0. 前置：MySQL + Redis + Java(8081) + Milvus Docker 已就绪
docker start milvus-standalone   # Milvus 没跑时

# 1. 配置（虚拟环境已在项目内 .venv，Python 3.11）
cp .env.example .env             # 填 DEEPSEEK_API_KEY / SILICONFLOW_API_KEY

# 2. （可选）西安版数据落地：备份→替换 MySQL→重建 Redis GEO
.venv/python.exe scripts/apply_xian_data.py

# 3. 建知识库（离线脚本；Milvus 单写者，先停 FastAPI）
.venv/python.exe scripts/ingest.py --source all

# 4. 启动服务
.venv/python.exe run.py          # http://127.0.0.1:8000/docs 看接口

# 5. 探活 + 浏览器 http://localhost:8080 → 底部「AI 助手」
bash scripts/demo_check.sh
```

## 常见问题

- **Milvus 503「channel not available」**：segment 本地存储损坏（容器被强杀/换镜像版本复用旧数据卷）。
  修复：drop 损坏 collection 后重跑 ingest（数据全可重建）：
  `python -c "from pymilvus import MilvusClient; MilvusClient(uri='http://127.0.0.1:19530').drop_collection('changan_kb')"`
- **pip 安装超时**：清华镜像偶发抽风，换 `--index-url https://mirrors.aliyun.com/pypi/simple/`。
- **SSE 全挤在最后一次性输出**：nginx 对应 location 缺 `proxy_buffering off`（已配好，勿删）。
- **换 embedding 模型后检索质量骤降**：必重建库（向量空间变了），重跑 ingest 即可。
